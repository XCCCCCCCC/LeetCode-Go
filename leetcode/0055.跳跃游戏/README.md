# [55. 跳跃游戏](https://leetcode.cn/problems/jump-game/)

## 解题思路

### 1. 我的思路

参考 121 题维护历史最低价格的方式，把过去所有跳跃方案压缩成一个最有用的状态：

```text
max 保存目前能够到达的最远下标。
```

遍历到下标 `i` 时：

- 如果 `i <= max`，说明当前位置能够到达，可以使用 `nums[i]` 更新最远距离；
- 如果 `i > max`，说明当前位置已经超过此前所有位置能够覆盖的范围，无法继续前进，直接返回 `false`。

更新公式：

```js
max = Math.max(max, i + nums[i])
```

其中：

```text
i + nums[i]
```

表示从当前位置最远可以跳到的下标。

### 2. 为什么不需要真的选择每次跳几步

题目只问“能否到达终点”，不要求给出具体跳跃路线，也不要求跳跃次数最少。

因此不需要在每个位置决定：

```text
这次究竟跳 1 步、2 步，还是跳到最远？
```

只需要关注所有已到达位置共同形成的最远覆盖范围。

例如：

```text
nums = [2,3,1,1,4]
```

| 当前下标 `i` | `nums[i]` | 处理前最远位置 | 当前可到达 | 更新后最远位置 |
|---:|---:|---:|---:|---:|
| 0 | 2 | 0 | `0 <= 0` | 2 |
| 1 | 3 | 2 | `1 <= 2` | 4 |
| 2 | 1 | 4 | `2 <= 4` | 4 |
| 3 | 1 | 4 | `3 <= 4` | 4 |
| 4 | 4 | 4 | `4 <= 4` | 8 |

遍历能够到达最后一个下标，所以返回 `true`。

### 3. 为什么遇到 `i > max` 可以立即失败

假设遍历到下标 `i` 时：

```text
i > max
```

`max` 已经综合了前面所有可达位置的跳跃能力。如果这些位置最远只能覆盖到 `max`，那么 `max + 1` 到 `i` 之间就出现了无法跨越的空缺。

因为后面的任何位置都必须先经过这个空缺才能到达，所以没有必要继续遍历，可以直接返回 `false`。

例如：

```text
nums = [3,2,1,0,4]
```

前四个位置最远只能覆盖到下标 `3`。当遍历准备进入下标 `4` 时：

```text
i = 4
max = 3
```

下标 `4` 不可达，因此返回 `false`。

### 4. 和 121 题的联系

两道题的具体状态不同，但优化方式相似：都不保留完整历史，只保留对未来最有价值的信息。

```text
121：过去只保留最低价格 minPrice
55：过去只保留最远可达下标 max
```

这是一类常见的贪心优化：

> 如果一个更优状态已经完全覆盖了较差状态，就只保留更优状态。

在本题中，如果一种走法能够到达下标 `5`，另一种只能到达下标 `3`，那么对于判断后续位置是否可达，能够到达 `5` 的状态已经包含了能够到达 `3` 的能力，不需要分别保存两条路线。

### 5. 核心不变量

在处理下标 `i` 之前：

```text
max 表示通过所有已经确认可达的位置，能够到达的最远下标。
```

只有满足：

```js
i <= max
```

当前位置才是可达的，也才有资格用 `i + nums[i]` 扩展覆盖范围。

处理完当前位置后，不变量继续成立：

```js
max = Math.max(max, i + nums[i])
```

### 6. 当前写法评估

```js
var canJump = function (nums) {
  let max = 0

  for (let i = 0; i < nums.length; i++) {
    if (i > max) {
      return false
    }

    max = Math.max(max, nums[i] + i)
  }

  return true
}
```

算法逻辑正确。当前代码中的：

```js
let result = true
```

没有被使用，可以删除。变量 `max` 也可以命名为 `maxReach`，更容易看出它表示最远可达下标，而不是数组中的最大值。

还可以在更新后提前成功：

```js
if (maxReach >= nums.length - 1) {
  return true
}
```

不过这只是少遍历几个位置，不影响算法复杂度，也不是必须修改。

## 边界条件

- 只有一个元素：起点就是终点，返回 `true`；
- 第一个元素为 `0` 且数组长度大于 1：无法离开起点，返回 `false`；
- 中间出现 `0`：不一定失败，只要此前的最远覆盖范围能够跨过去即可；
- 最远位置超过数组末尾：说明一定能够到达终点；
- 判断不可达必须使用 `i > max`，当 `i === max` 时当前位置仍然可以到达。

时间复杂度：`O(n)`，每个位置最多遍历一次。

空间复杂度：`O(1)`，只维护最远可达下标。

## 题目说明（本地训练版）

数组中每个元素表示从当前位置最多可跳的距离，判断能否到达末尾。

### 官方示例

#### 示例 1

```text
nums = [2,3,1,1,4]
输出 = true
```

#### 示例 2

```text
nums = [3,2,1,0,4]
输出 = false
```

### 约束与训练提示

- 1 <= nums.length <= 10^4
- 0 <= nums[i] <= 10^5
- 遍历过程中维护当前能到达的最远位置。
- 如果当前下标已超过最远可达位置则失败。
