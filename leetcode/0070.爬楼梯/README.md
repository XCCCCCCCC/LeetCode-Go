# [70. 爬楼梯](https://leetcode.cn/problems/climbing-stairs/)

## 解题思路

### 1. 当前代码：用递归枚举所有走法

每次只能走 1 阶或 2 阶，因此每到一个位置都有两个选择。`backTrace(total)` 中，`total` 表示当前已经走到的阶数；递归调用 `backTrace(total + 1)` 和 `backTrace(total + 2)` 分别表示走 1 阶和走 2 阶。

### 2. 两个终止条件

刚好到达 `n` 阶时：

```js
if (total === n) {
  result += 1
  return
}
```

这代表找到一条完整路线，方案数加 1。

超过 `n` 阶时：

```js
if (total > n) {
  return 0
}
```

这条路线已经超过楼顶，不是合法方案，立即结束。当前外层没有接收这个返回值，写成 `return` 也可以。

### 3. 当前代码为什么能正确

代码从 `0` 阶开始，枚举走 1 阶或 2 阶的所有组合。每条路径最终只有两种结果：刚好到 `n`，贡献 1；超过 `n`，贡献 0。所有合法路径都会被枚举一次，因此 `result` 就是总方案数。

以 `n = 3` 为例，合法路线是：

```text
0 -> 1 -> 2 -> 3
0 -> 1 -> 3
0 -> 2 -> 3
```

所以答案是 3。

## 回溯和普通递归的区别

你这版严格来说更像“递归枚举”，因为没有维护可变路径数组，也没有执行“做选择 → 递归 → 撤销选择”。但它仍然是在每个状态尝试所有选择，遇到合法终点统计，遇到非法状态剪枝。

本题不需要 `temp.push()` 和 `temp.pop()`，因为只关心当前走了多少阶，不需要记录完整路径；把 `total` 作为递归参数，就已经保存了当前状态。

## 从回溯观察到动态规划

回溯虽然正确，但会重复计算相同状态。无论通过哪条路线到达同一个阶数，后面到达终点的方案数都相同，这就是动态规划的切入点。

定义：

```text
dp[i]：到达第 i 阶的方案数
```

到达第 `i` 阶的最后一步只有两种可能：从第 `i - 1` 阶走 1 阶，或从第 `i - 2` 阶走 2 阶。因此：

```text
dp[i] = dp[i - 1] + dp[i - 2]
```

初始值为 `dp[1] = 1`、`dp[2] = 2`。空间压缩后只需要保存前两个状态，DP 的时间复杂度是 `O(n)`，空间复杂度是 `O(1)`。

### 1. func2：空间压缩 DP

你写的 `func2`：

```js
var climbStairs_func2 = function (n) {
  let prev1 = 1
  let prev2 = 2

  for (let i = 3; i <= n; i++) {
    const cur = prev1 + prev2
    prev1 = prev2
    prev2 = cur
  }

  return prev2
}
```

这已经是正确的空间压缩方向。

变量含义是：

```text
prev1：前两阶的方案数，开始时表示 dp[1]
prev2：前一阶的方案数，开始时表示 dp[2]
cur：当前第 i 阶的方案数
```

每轮计算前，`prev1 = dp[i - 2]`、`prev2 = dp[i - 1]`；更新后，`prev1 = dp[i - 1]`、`prev2 = dp[i]`。因此循环结束时 `prev2` 就是 `dp[n]`。

### 2. func2 的边界问题

当前初始化直接使用 `prev1 = 1`、`prev2 = 2`。当 `n = 1` 时，循环不会执行，函数会返回 `2`，但正确答案是 `1`。

需要先处理基础情况：

```js
if (n <= 2) {
  return n
}
```

修正后的版本：

```js
var climbStairs_func2 = function (n) {
  if (n <= 2) {
    return n
  }

  let prev1 = 1
  let prev2 = 2

  for (let i = 3; i <= n; i++) {
    const cur = prev1 + prev2
    prev1 = prev2
    prev2 = cur
  }

  return prev2
}
```

### 3. 动态规划题是不是都要先判断边界

不一定。更准确的说法是：

> 每道 DP 题都必须明确初始状态，但初始状态不一定都要用 `if` 提前返回。

常见有两种写法。

#### 写法一：提前返回边界，再处理通用递推

本题使用：

```js
if (n <= 2) {
  return n
}
```

原因是通用递推从 `i = 3` 开始：

```js
dp[i] = dp[i - 1] + dp[i - 2]
```

当 `n` 是 1 或 2 时，循环不需要执行，直接返回已知答案最清楚。

#### 写法二：把边界放进 DP 初始化

也可以不提前返回，而是初始化基础状态：

```js
const climbStairsDP = (n) => {
  const dp = new Array(n + 1).fill(0)

  dp[0] = 1
  if (n >= 1) dp[1] = 1

  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2]
  }

  return dp[n]
}
```

两种写法本质相同，只是把边界放在函数入口，还是放在 DP 表初始化中。

### 4. 如何判断要不要提前返回

写 DP 时按下面顺序检查：

```text
1. dp[i] 表示什么？
2. 递推公式从哪个 i 开始成立？
3. 公式开始前需要哪些初始值？
4. n 可能落在初始范围内吗？
```

如果 `n` 可能直接落在初始范围内，就可以：

```text
提前返回边界答案
或初始化边界状态，让循环自然处理
```

不要机械地给每道题都添加很多 `if`。边界判断的目的只有一个：防止访问不存在的状态，或者让递推公式在不适用的下标上运行。

### 5. 为什么可以只保留两个变量

完整 DP 会保存 `dp[1]` 到 `dp[n]`，但计算 `dp[i]` 时只依赖 `dp[i - 1]` 和 `dp[i - 2]`。更早的状态以后不会再使用，因此可以丢弃，这叫空间压缩。

## 核心不变量

```text
total 表示当前路径已经走到的阶数
result 表示已经找到的合法完整路线数量
```

递归结束时，`total === n` 使 `result` 增加 1，`total > n` 不增加结果。

## 边界条件

- `n = 1`：只有走 1 阶一种方式，返回 `1`；
- `n = 2`：`1 + 1`、`2`，返回 `2`；
- 超过 `n`：立即结束当前分支；
- `dic = [1, 2]` 实际表示每次可选择的步数，命名为 `choices` 会更准确。

当前回溯时间复杂度约为 `O(2^n)`，递归栈空间为 `O(n)`；`func2` 时间复杂度为 `O(n)`，空间复杂度为 `O(1)`。
