# [有效的括号](https://leetcode.cn/problems/valid-parentheses/)

给定一个只包括 '('，')'，'{'，'}'，'['，']' 的字符串 s ，判断字符串是否有效。

有效字符串需满足：

1. 左括号必须用相同类型的右括号闭合。
2. 左括号必须以正确的顺序闭合。

示例1：
```
输入：s = "()"
输出：true
```

示例2：
```
输入：s = "()[]{}"
输出：true
```

示例3：
```
输入：s = "(]"
输出：false
```

示例4：
```
输入：s = "([)]"
输出：false
```

示例5：
```
输入：s = "{[]}"
输出：true
```

## 解题思路

### 1. func1 是否正确

当前 `func1` 在题目限定字符串只包含 `()[]{}` 的前提下是正确的。

代码使用 `Map` 保存右括号与左括号的对应关系：

```text
) -> (
] -> [
} -> {
```

遍历到一个字符时：

- 如果当前字符是右括号，并且栈顶正好是与它匹配的左括号，就弹出栈顶；
- 否则把当前字符压入栈中；
- 最后栈为空，说明所有括号都完成了正确匹配。

例如：

```text
s = "{[]}"

读取 {：[{]
读取 [：[{, []
读取 ]：[{]       // [ 与 ] 匹配，出栈
读取 }：[]        // { 与 } 匹配，出栈
```

最终栈为空，因此返回 `true`。

官方案例和长度 0～6 的所有括号组合均已验证通过。

### 2. 当前写法可以改进的地方

当前写法遇到无法匹配的右括号时，也会把右括号压入栈中：

```text
s = "]"
stack = ["]"]
```

最终仍然会因为栈不为空而正确返回 `false`，所以结果没有问题。但是这样会让栈里同时出现左括号和错误的右括号，栈的含义不够统一。

更标准的做法是规定：

> 栈中只保存尚未匹配的左括号。

这样遍历到右括号时，如果栈为空或者栈顶不匹配，就可以立刻返回 `false`，不需要继续遍历。

推荐写法：

```js
const isValid = (s) => {
  const stack = []
  const pairs = new Map([
    [')', '('],
    [']', '['],
    ['}', '{']
  ])

  for (const char of s) {
    if (!pairs.has(char)) {
      // 左括号暂时无法处理，等待后面的右括号
      stack.push(char)
      continue
    }

    // 当前是右括号，必须与最近的左括号匹配
    if (stack.pop() !== pairs.get(char)) {
      return false
    }
  }

  return stack.length === 0
}
```

`stack.pop()` 在空栈时会得到 `undefined`，也会与左括号匹配失败，因此不需要额外判断空栈。

### 3. 为什么这道题必须匹配栈顶

括号不只是数量相等，还要求嵌套顺序正确。

例如：

```text
([)]
```

读取到 `)` 时，最近一个还没有匹配的左括号是 `[`，而不是 `(`。因此必须判定为错误。

这就是栈“后进先出”的作用：

```text
最后出现的左括号，必须最先被右括号关闭。
```

如果只是分别统计三种括号的数量，就无法识别 `([)]` 这种数量正确、顺序错误的情况。

### 4. 本题的核心不变量

遍历到任意位置时：

> 栈中按照出现顺序保存了所有尚未匹配的左括号，栈顶是接下来必须优先匹配的左括号。

这句话就是本题全部逻辑的依据。

## 栈题型整体框架

### 1. 栈到底是什么

栈可以理解成一摞盘子：

```text
放盘子：只能放到最上面
拿盘子：只能拿最上面的
```

因此它具有“后进先出”的特点：

```text
最后放进去的，最先被处理。
```

JavaScript 通常直接使用数组模拟栈：

```js
const stack = []

stack.push(value)        // 入栈
stack.pop()              // 出栈并取得栈顶元素
stack[stack.length - 1]  // 查看栈顶但不删除
stack.length === 0       // 判断是否为空
```

### 2. 什么题应该想到栈

如果题目存在下面这些描述，可以尝试考虑栈：

- 当前内容需要和“最近一个尚未处理的内容”配对；
- 遇到某个结束标志后，需要返回上一个处理现场；
- 处理顺序具有明显的嵌套结构；
- 需要寻找左边或右边第一个更大、更小的元素；
- 一个元素暂时无法得到答案，需要等待后面的元素处理它。

最通俗的判断方法是：

> 当前元素来了以后，是不是应该优先处理最近留下来的问题？

如果答案是“是”，通常就具有栈的特征。

### 3. 做栈题固定问三个问题

每道栈题先不要急着写代码，先回答：

```text
1. 栈里保存什么？
2. 什么情况下入栈？
3. 什么情况下出栈？
```

对于第 20 题：

```text
栈里保存什么：尚未匹配的左括号
什么时候入栈：遇到左括号
什么时候出栈：遇到能够匹配栈顶的右括号
```

如果遇到右括号却无法匹配栈顶，就直接失败。

### 4. Hot100 栈题的四个层次

#### 第一类：匹配与消除

代表题：20. 有效的括号。

核心含义：栈中保存“最近还没有被匹配的内容”。

常见框架：

```js
for (const item of items) {
  if (item 暂时不能处理) {
    stack.push(item)
  } else {
    const previous = stack.pop()
    // 使用当前 item 处理 previous
  }
}
```

#### 第二类：同步保存额外状态

代表题：155. 最小栈。

普通栈只保存元素，但题目还要求随时获得当前最小值。解决方式是让每次入栈时，同时保存这一层对应的最小值。

重点问题：

```text
一个元素出栈以后，怎样立刻恢复到上一层的状态？
```

#### 第三类：保存处理现场

代表题：394. 字符串解码。

遇到嵌套内容时，当前层暂时无法完成，就把当前字符串、重复次数等信息压栈；处理完内层以后，再出栈回到外层。

它很像：

```text
进入下一层前保存现场，完成下一层后恢复现场。
```

#### 第四类：单调栈

代表题：739. 每日温度、84. 柱状图中最大的矩形。

栈中的元素不是随便排列，而是始终保持单调递增或单调递减。

核心含义：

```text
栈中保存的是暂时还没有找到答案的元素。
```

当一个新元素到来并且能够解决栈顶元素的问题时，就不断出栈并计算答案。

例如每日温度中，栈里保存“还没有等到更高温度的日期下标”。遇到更高温度时，就可以依次处理栈顶日期。

### 5. 普通栈与单调栈的区别

普通栈重点关注处理顺序：

```text
最近留下的问题优先处理。
```

单调栈除了关注顺序，还要求栈内元素保持某种大小关系：

```text
单调递增或单调递减。
```

刚开始学习栈时，不需要立刻把单调栈完全搞懂。先通过 20、155、394 熟悉“保存未完成内容”和“恢复现场”，再学习 739 的单调栈会更自然。

### 6. 常见错误

- 没有明确栈里保存的是值、下标，还是某一层的状态；
- 遇到右括号时没有先判断栈是否能够匹配；
- 只检查过程中是否匹配，忘记最后判断栈是否为空；
- `pop()` 后又读取栈顶，混淆了被弹出的元素和新的栈顶；
- 单调栈题只写一个 `if`，实际上可能需要连续弹出多个元素，因此通常使用 `while`。

### 7. 复杂度

第 20 题中，每个字符最多入栈一次、出栈一次：

- 时间复杂度：`O(n)`；
- 空间复杂度：`O(n)`，最坏情况下所有字符都是左括号。
