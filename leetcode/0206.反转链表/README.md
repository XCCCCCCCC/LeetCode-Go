# [206. 反转链表](https://leetcode.cn/problems/reverse-linked-list/)

## 解题思路

### 先理解“反转”的对象

链表不是数组。数组中的元素通过下标保持顺序，单链表中的顺序则由每个节点的 `next` 决定：

```text
1 → 2 → 3 → null
```

反转链表不是把节点的值倒着复制一遍，而是把节点之间的箭头逐个改向：

```text
原来：1 → 2 → 3 → null
反转：null ← 1 ← 2 ← 3
```

完成后，从新的头节点 `3` 出发就是：

```text
3 → 2 → 1 → null
```

### 当前写法：三个引用原地反转

当前代码中的三个变量分别负责：

```text
prev：已经完成反转的前半段链表的头节点
cur：当前准备处理的节点
next：暂时保存 cur 原来的下一个节点
```

初始状态：

```text
prev = null
cur  = head
```

每轮循环处理一个节点，四行代码的顺序非常重要：

```js
let next = cur.next // 1. 先保存后面的链表
cur.next = prev     // 2. 把当前箭头反过来
prev = cur          // 3. 扩大已经反转的区域
cur = next          // 4. 继续处理原链表的下一个节点
```

以 `1 → 2 → 3 → null` 为例：

```text
开始：prev = null        cur = 1 → 2 → 3 → null

第1轮：prev = 1 → null   cur = 2 → 3 → null
第2轮：prev = 2 → 1      cur = 3 → null
第3轮：prev = 3 → 2 → 1 cur = null
```

当 `cur === null` 时，说明原链表中的所有节点都处理完了。此时：

- `cur` 已经越过最后一个节点；
- `prev` 指向反转后链表的第一个节点；
- 原来的 `head` 已经变成尾节点，并且它的 `next` 是 `null`。

所以最后必须返回 `prev`，而不是返回原来的 `head`。

### 为什么必须先保存 `next`

执行下面这行代码后：

```js
cur.next = prev
```

`cur.next` 原来保存的后继关系会被覆盖。如果没有提前执行：

```js
let next = cur.next
```

程序就找不到尚未处理的后半段链表了。这是反转链表最容易出现的错误。

核心不变量：每轮开始时，`prev` 指向已经反转完成的链表，`cur` 指向尚未处理的链表；每轮只把 `cur` 这一个节点从未处理区域移动到已反转区域。

每个节点只访问一次，也只修改一次 `next`：

```text
时间复杂度：O(n)
空间复杂度：O(1)
```

## 边界条件

- 空链表：`cur` 初始就是 `null`，循环不会执行，最终返回 `prev`，也就是 `null`。
- 只有一个节点：执行一轮后，该节点仍然指向 `null`，然后作为新头节点返回。
- 两个节点：适合用来手动检查四条语句的执行顺序。
- 不能先修改 `cur.next` 再保存后继节点，否则会丢失剩余链表。
- 返回的是 `prev`，不是原来的 `head`；原来的头节点反转后已经成为尾节点。

## 题目说明（本地训练版）

反转一条单链表并返回新的头节点。

### 官方示例

#### 示例 1

```text
head = [1,2,3,4,5]
输出 = [5,4,3,2,1]
```

#### 示例 2

```text
head = [1,2]
输出 = [2,1]
```

#### 示例 3

```text
head = []
输出 = []
```

### 约束与训练提示

- 链表中节点的数目范围是 [0, 5000]
- -5000
- 更改 next 之前必须保存原后继节点。
- 空链表和单节点链表应直接返回。
