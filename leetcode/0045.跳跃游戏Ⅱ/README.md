# [跳跃游戏II](https://leetcode.cn/problems/jump-game-ii/)

给你一个非负整数数组 nums ，你最初位于数组的第一个位置。

数组中的每个元素代表你在该位置可以跳跃的最大长度。

你的目标是使用最少的跳跃次数到达数组的最后一个位置。

假设你总是可以到达数组的最后一个位置。

示例1：
```
输入: nums = [2,3,1,1,4]
输出: 2
解释: 跳到最后一个位置的最小跳跃数是 2。
     从下标为 0 跳到下标为 1 的位置，跳 1 步，然后跳 3 步到达数组的最后一个位置。
```

示例2：
```
输入: nums = [2,3,0,1,4]
输出: 2
```

## 解题思路

### 1. 这道题和 55 题的区别

55 题只问：

```text
能不能到达终点？
```

所以只维护一个最远可达位置即可。

45 题问的是：

```text
最少需要跳几次？
```

因此除了维护最远位置，还需要知道：

```text
当前这一次跳跃最多能覆盖到哪里？
下一次跳跃最多能覆盖到哪里？
已经使用了几次跳跃？
```

### 2. func1：按候选位置选择下一跳

你的 `func1` 思路是：

1. 站在当前下标 `cur`；
2. 枚举当前一步能够跳到的所有位置；
3. 选择能够继续覆盖最远位置的候选下标；
4. 跳到这个位置，重复以上过程。

例如：

```text
nums = [2,3,1,1,4]
```

从下标 `0` 可以到 `1` 或 `2`：

```text
到 1 后最远可到 1 + 3 = 4
到 2 后最远可到 2 + 1 = 3
```

所以选择下标 `1`，再跳到终点。

这个贪心选择是合理的：

> 在当前一步能够到达的范围内，选择能为下一步带来最远覆盖范围的位置。

`func1` 在官方测试和小规模可达数组对拍中没有发现结果错误，但实现包含递归式的手动边界处理，复杂度和可读性都不如下面的“按覆盖区间”写法。

### 3. func2 调整版：局部状态的方向是对的

你这次把 `count` 和 `next` 放进 `recur` 内部：

```js
function recur(index) {
  let count = 0
  let next = 0
  // ...
}
```

这是一次进步。现在每次递归都表示“从当前 `index` 重新选择下一跳”，这一层的候选最远位置和下一跳下标应该独立计算，不应该继续混用上一层的临时选择。

前一版本存在几个问题，本次已经完成修正；下面保留这些问题作为复盘记录。

```js
let step = 0
let count = 0
let next = 0
```

#### 问题一：单元素数组会多算一次

```js
nums = [1]
```

已经在终点，正确答案是 `0`。但 `recur(0)` 一进入就执行：

```js
step++
```

因此返回 `1`。

这说明 `step` 的增加时机不对：应该在真正跨过当前覆盖边界、确定要进行下一跳时增加，而不是一进入递归就增加。

#### 问题二：候选位置的覆盖公式写错

当前写法：

```js
if (index + nums[i] > count) {
  next = i
  count = index + nums[i]
}
```

正在评估的是“落到候选位置 `i` 后，下一步能到哪里”，所以应该使用：

```js
i + nums[i]
```

而不是：

```js
index + nums[i]
```

`index` 是当前所在位置，`i` 才是准备跳到的位置。两者不能混淆。

你这次的代码虽然把判断条件仍写成了 `index + nums[i]`，但赋值时已经写成了 `i + nums[i]`：

```js
if (index + nums[i] > count) {
  next = i
  count = i + nums[i]
}
```

这会导致“用一种公式决定是否更新，用另一种公式保存结果”。两个地方必须统一使用：

```js
const reach = i + nums[i]

if (reach > count) {
  count = reach
  next = i
}
```

最小反例：

```text
nums = [2,1,1,0]
```

从下标 0 可以选择：

```text
跳到 1：1 + nums[1] = 2
跳到 2：2 + nums[2] = 3
```

应该选择下标 2，两跳到达终点；当前判断却把两个候选都按 `index + nums[i]` 比较，可能错误选择下标 1，结果变成 3 跳。

#### 问题三：终点下标和数组长度混淆

最后一个位置的下标是：

```js
nums.length - 1
```

不是：

```js
nums.length
```

例如：

```text
nums = [1,2,0]
```

下标 `1` 可以直接跳到下标 `2`，答案应该是 `2`：

```text
0 -> 1 -> 2
```

但你的代码在第一次扫描时发现候选位置 `1` 的覆盖范围已经达到数组长度，就直接返回当前 `step = 1`，少算了一跳。

#### 问题四：提前返回时，`step` 仍然少算

递归进入 `index` 时，代码立即：

```js
step++
```

但此时还没有确定从 `index` 跳到哪里。与此同时，在当前循环中发现下一候选位置可以到达终点时，又直接使用当前 `step` 返回。

例如：

```text
nums = [1,2,0]
```

从下标 0 选择下标 1 后，实际上还需要第二跳到下标 2：

```text
0 -> 1 -> 2
```

但当前代码在扫描到候选位置 1 时就执行：

```js
step++
return
```

此时 `step` 只记录了从 0 走向候选位置的这一层，不能因为“候选位置未来能到终点”就把当前层直接当成完成。

更简单的方式是：不要在扫描候选位置时提前返回；先选出 `next`，再统一执行一次：

```js
step++
recur(next)
```

当 `next` 本身就是最后下标时，下一次递归自然结束。

#### 问题五：`step` 的语义混合了“已走到当前点”和“即将进行的跳跃”

递归进入 `index` 时，代码立即：

```js
step++
```

但此时还没有确定从 `index` 跳到哪里。与此同时，在当前循环中发现下一候选位置可以到达终点时，又直接使用当前 `step` 返回。

因此同一个变量既像是在表示：

```text
已经跳了几次
```

又像是在表示：

```text
当前这轮正在选择第几次跳跃
```

这会产生 `func2` 中的少算或多算问题。

#### 问题六：函数最后没有返回 `step`

当前函数末尾是：

```js
recur(0)
}
```

缺少：

```js
return step
```

因此即使内部计算出了正确的跳数，调用 `jump_func2` 仍然会得到 `undefined`。

#### 问题七：递归不是本题最自然的表达

数组长度最多为 `10^4`，如果递归层数较深，会有调用栈风险；而且每一轮都重新扫描候选范围，最坏复杂度也可能达到 `O(n²)`。

### 4. 本次修正后的结果

当前 `func2` 已完成以下修正：

```text
1. 单元素数组直接返回 0；
2. 当前点可以直接到终点时，跳数加一后结束；
3. 候选位置统一使用 i + nums[i] 计算后续覆盖范围；
4. 当前层选择 next 后，step 只增加一次；
5. 函数最后返回 step。
```

之前的反例 `[1]`、`[1,2,0]`、`[2,1,1,0]`、`[3,0,0,0]` 均已通过；小规模可达数组穷举对拍也通过。

当前递归写法仍然可能重复扫描候选区间，时间复杂度最坏可能达到 `O(n²)`，递归深度也可能达到 `O(n)`。因此它适合作为理解“选择下一跳最远位置”的过渡版本，最终复习时建议掌握后面的区间贪心模板。

### 5. 推荐理解：把位置看成一层一层的覆盖区间

不要每次真的挑出一个具体落点，可以把一次跳跃能够到达的所有位置看成一层：

```text
当前跳跃覆盖区间：[0, currentEnd]
```

扫描这个区间里的所有位置，计算下一跳最远能覆盖到哪里：

```text
nextEnd = max(i + nums[i])
```

当扫描到当前区间的边界 `currentEnd` 时，说明这一跳能覆盖的范围已经全部看完，必须使用一次跳跃，并把边界扩展到 `nextEnd`。

这和 BFS 的“按层遍历”很像：

```text
第 0 层：起点
第 1 层：从起点一步能到的所有位置
第 2 层：从第 1 层继续一步能到的所有位置
```

因为每一层代表固定的跳跃次数，所以第一次覆盖到终点时，跳跃次数一定最少。

### 6. 推荐模板

```js
const jump = (nums) => {
  let jumps = 0
  let currentEnd = 0
  let nextEnd = 0

  // 最后一格不需要再从它跳出去
  for (let i = 0; i < nums.length - 1; i++) {
    nextEnd = Math.max(nextEnd, i + nums[i])

    // 当前这一跳的覆盖范围扫描完成
    if (i === currentEnd) {
      jumps++
      currentEnd = nextEnd
    }
  }

return jumps
}
```

如果你想暂时保留“递归选择具体下一跳”的思路，至少要遵循下面的状态定义：

```text
recur(index)：当前位于 index
step：已经完成的跳跃次数
count：本层候选位置中，下一步能够覆盖的最远下标
next：达到 count 的候选位置
```

每层应该先选完 `next`，再统一：

```js
step++
recur(next)
```

不要在发现某个候选位置能覆盖终点时直接使用当前 `step` 返回，因为候选位置本身可能还需要先通过一次跳跃才能到达。

### 7. 用 `[2,3,1,1,4]` 走一遍

| 下标 `i` | `nums[i]` | 当前层边界 `currentEnd` | 下一层最远 `nextEnd` | 是否换层 | 跳数 |
|---:|---:|---:|---:|---|---:|
| 0 | 2 | 0 | 2 | 是 | 1 |
| 1 | 3 | 2 | 4 | 否 | 1 |
| 2 | 1 | 2 | 4 | 是 | 2 |

扫描到下标 `2` 时，下一层已经覆盖到下标 `4`，终点到达，返回 `2`。

注意：当 `i === currentEnd` 时，不是在选择“当前下标作为落点”，而是在表示：

> 当前这次跳跃能覆盖的区域已经扫描完，现在必须把跳跃次数加一，并切换到下一层覆盖范围。

### 8. 和 55 题的联系

```text
55：维护一个 maxReach，判断终点是否可达
45：维护 currentEnd 和 nextEnd，统计覆盖多少层
```

两题都在维护最远可达范围，但目标不同：

```text
55 只关心能不能覆盖到终点
45 还要记录覆盖到终点经历了几层
```

## 核心不变量

使用区间模板时：

```text
currentEnd：当前已经使用的跳数能够覆盖到的最远边界
nextEnd：在扫描当前边界之前，下一次跳跃能够覆盖到的最远位置
jumps：到达当前覆盖层所需要的跳跃次数
```

遍历到 `i` 时，必须保证 `i <= currentEnd`；题目保证一定可达，因此不会出现不可达情况。

当 `i === currentEnd`：

```text
当前层扫描结束
jumps 加一
currentEnd 更新为 nextEnd
```

时间复杂度：`O(n)`，每个位置只扫描一次。

空间复杂度：`O(1)`，只使用固定数量的变量。
